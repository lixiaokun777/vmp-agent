# Agent 架构设计

## 组件

- `cmd/agent`：配置加载、注册、心跳、库存刷新和任务轮询。
- `cmd/agent/state.go`：宿主专属凭据、单任务日志、原子持久化和进程锁。
- `cmd/agent/workers.go`：独立心跳/库存/任务 worker、任务租约续租和结果确认恢复。
- `internal/agent`：控制面协议模型和虚拟化驱动接口。
- `internal/agent/kvm`：KVM/libvirt 预检、宿主机事实和域发现。
- `internal/agent/kvm/images.go`：安全根句柄、不可变缓存、真实 HTTPS 下载和镜像版本就绪。
- `internal/agent/kvm/cache_gc.go`：完整虚机 backing 引用证明后的缓存压力回收，未知存储拒绝清理。
- `internal/agent/kvm/delivery.go`：Guest Agent IP/MAC、cloud-init 和 SSH 的分层交付，不因 ICMP 失败毁盘。
- `internal/console`：短时票据校验、VNC TCP 与串口 PTY 的 WebSocket 代理。
- `deployments/agent-bundle`：不依赖 systemd 的运行目录和管理脚本。

## 驱动边界

`Driver` 对外只暴露模式、检查和任务执行三类能力。后续支持 Proxmox、VMware 或其他虚拟化平台时，应实现新驱动，不将特定平台逻辑放入主循环。

## 存量资源保护

KVM 驱动默认将所有域标记为 `EXTERNAL`。仅当 libvirt XML 中的专用 namespace、`managed-by=vmlease` 和平台实例 UUID 同时合法时，才标记为 `MANAGED`。元数据似是而非时标记为 `UNKNOWN`，不得自动操作。

## 交付计划层

`BuildProvisionPlan` 是写操作前的纯函数安全边界。它只生成实例目录、基础镜像、系统盘、seed ISO 路径，以及域 XML、cloud-init meta-data、user-data 和 network-config，不进行任何 I/O。

输入校验覆盖实例 UUID、名称、CPU、内存、磁盘、镜像路径穿越、网桥白名单、MAC、IPv4、DNS、用户名和多行凭据注入。域 XML 携带平台元数据，使后续盘点能识别托管关系。

当前计划已接入受控的分步执行器。创建流程依次写入平台清单和 cloud-init 文件、识别基础镜像格式、创建 qcow2 增量盘、制作 seed ISO、定义并启动域。失败时先写补偿标记，并查询托管域实际状态；只有确认停止、取消定义且域确实不存在后才清理本次创建目录。状态不确定时保盘，后续重试执行安全补偿。

删除流程在任何破坏性命令前，会同时校验 libvirt 域的平台元数据和实例目录的 `manifest.json`。外部域、实例 UUID 不匹配、名称不匹配、符号链接目录或清单异常时都会拒绝删除。

`kvm-readonly` 仍会在 `Execute` 入口拒绝所有任务。写模式需要 `AGENT_MODE`、布尔开关和固定确认短语三重门禁。

## worker 与恢复边界

心跳每 10 秒、库存每 60 秒、任务领取每 2 秒，由三个独立 worker 驱动；库存采用最多 90 秒的上下文，心跳最多 5 秒，快照通过读写锁交换。执行任务不会阻断宿主在线判断，单个任务 worker 串行运行，私有状态目录进程锁防止重复启动。

任务先持久化领取记录，执行后先持久化结果再上报。控制面确认前不清空记录，重启恢复优先处理旧记录而不是领取新任务。租约每 10 秒续租，原租约截止前无法续上则取消执行；SIGTERM、工作超时和租约丢失均只记录本地补偿标记保留现场，不能通过后台上下文继续破坏性回滚。

成功结果在旧领取令牌失效后可随同一个任务和相同负载的新领取令牌再次确认；失败结果不能作为下一次尝试的结果复用。执行中断的重启属于不可确定副作用，明确报错并人工核查，避免重复重启业务机。

未确认成功结果按摘要分条隔离，另一任务不能覆盖或清理；只在对应任务确认后清除。最多 256 条，超限保留现场并停止领取，管理员核查后再恢复。后端完成回执保留 60 天；长期离线超过该窗口的删除完成任务可能已清表，旧 token 返回冲突而无法自动消除缓存，需要核查真实域、控制面记录后人工处理，不能假设无限期 exactly-once。

## 控制台边界

控制台不经过任务轮询传输交互数据。Agent 上报仅控制节点可达的内部地址，浏览器使用控制面同源 WebSocket 代理；后台固定目标宿主管理 IP/端口，不向浏览器暴露 Agent URL。Agent 校验 HMAC、宿主 ID、模式、域名、时效、原平台 Origin 并核销 session_id；重复核销拒绝。VNC 目标限定回环，串口仅票据受管域，19090 仅控制节点可达。

在核销前实时读取 libvirt XML，域 UUID 必须等于平台实例 UUID，域名、命名空间及 managed-by/instance-id 元数据必须一致，并验证运行状态。后续命令使用 UUID 而非名称；底层 VNC TCP 或串口 PTY 打开后、接受 WebSocket 前再次校验，替换域或状态改变则关闭底层连接。票据不授予开机或接管外部域的权限。

## 预算与就绪

固定总预算和真实余量分别上报，`resource_measured_at` 在读取资源时固定，重复心跳不刷新旧读数。目录清单包含镜像 generation/摘要、网络 bridge，Agent 上报完整性与逐宿主真实就绪。控制面同时校验预算、测量后预占、读数新鲜度、镜像版本和网络，不得把静态总预算与动态 free 混为一谈。

源镜像通过 `os.OpenRoot` 打开并复制实际描述符到只读内容寻址缓存；最终 qemu backing 不重新打开可变原路径。远程镜像采用 HTTPS 白名单、私网子白名单、单次 DNS 校验固定 IP、不跟重定向、摘要/大小/磁盘安全边界。详细限制见 [镜像与交付安全](镜像与交付安全.md)。
