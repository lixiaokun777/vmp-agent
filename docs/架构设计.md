# Agent 架构设计

## 组件

- `cmd/agent`：配置加载、注册、心跳、库存刷新和任务轮询。
- `internal/agent`：控制面协议模型和虚拟化驱动接口。
- `internal/agent/kvm`：KVM/libvirt 预检、宿主机事实和域发现。
- `internal/console`：短时票据校验、VNC TCP 与串口 PTY 的 WebSocket 代理。
- `deployments/agent-bundle`：不依赖 systemd 的运行目录和管理脚本。

## 驱动边界

`Driver` 对外只暴露模式、检查和任务执行三类能力。后续支持 Proxmox、VMware 或其他虚拟化平台时，应实现新驱动，不将特定平台逻辑放入主循环。

## 存量资源保护

KVM 驱动默认将所有域标记为 `EXTERNAL`。仅当 libvirt XML 中的专用 namespace、`managed-by=vmlease` 和平台实例 UUID 同时合法时，才标记为 `MANAGED`。元数据似是而非时标记为 `UNKNOWN`，不得自动操作。

## 交付计划层

`BuildProvisionPlan` 是写操作前的纯函数安全边界。它只生成实例目录、基础镜像、系统盘、seed ISO 路径，以及域 XML、cloud-init meta-data、user-data 和 network-config，不进行任何 I/O。

输入校验覆盖实例 UUID、名称、CPU、内存、磁盘、镜像路径穿越、网桥白名单、MAC、IPv4、DNS、用户名和多行凭据注入。域 XML 携带平台元数据，使后续盘点能识别托管关系。

当前计划已接入受控的分步执行器。创建流程依次写入平台清单和 cloud-init 文件、识别基础镜像格式、创建 qcow2 增量盘、制作 seed ISO、定义并启动域。失败时会尝试取消域定义并清理本次创建的受控目录。

删除流程在任何破坏性命令前，会同时校验 libvirt 域的平台元数据和实例目录的 `manifest.json`。外部域、实例 UUID 不匹配、名称不匹配、符号链接目录或清单异常时都会拒绝删除。

`kvm-readonly` 仍会在 `Execute` 入口拒绝所有任务。写模式需要 `AGENT_MODE`、布尔开关和固定确认短语三重门禁。

## 控制台边界

控制台不经过任务轮询传输交互数据。Agent 将浏览器可达地址通过心跳上报，控制面校验用户与实例后签发 HMAC-SHA256 票据。Agent 校验票据签名、宿主机 ID、模式、域名、过期时间和 HTTP Origin，然后才建立本地代理。VNC 目标被限定为回环地址，串口目标只能是票据中的受管域名。
