# 镜像、实时资源与分层交付

## 资源预算不是剩余容量

`allocatable_cpu`、`allocatable_memory_mb`、`allocatable_disk_gb` 为配置的固定总预算；配置为自动时，依据 CPU 数、物理总内存/文件系统总容量和安全保留量计算，不随某台实例启动后下降。

同时上报 `facts.budget_source=CONFIGURED_TOTAL`、`safe_available_memory_mb`、`safe_available_disk_gb`、`resource_measured_at`。安全余量来自本次实际内存/磁盘读数，时间在读取资源时固定，随后重复心跳不能更新该时间。控制面还需要扣除测量后已预占的待交付资源，并限制读数新鲜度；不能把全部运行实例的 reserved 再从实际 free 中扣一次。

## 每个宿主的就绪矩阵

Agent 获取 `GET /api/v1/agents/{host_id}/catalog`，清单包含镜像 ID、来源、文件名、全局摘要、generation 和网络 bridge。宿主通过心跳上报：

| 字段 | 含义 |
| --- | --- |
| `facts.images[].image_id/file_name/checksum/generation/status/error` | 每个镜像版本在本宿主的真实校验结果 |
| `facts.networks[].bridge/ready/error` | 白名单中的实际 Linux bridge 是否存在并启用 |
| `facts.readiness_complete` | 清单已获取、检查未中断且没有被同步锁阻断 |
| `facts.resource_measured_at` | 真实资源测量时间，UTC RFC3339 |

本地模板始终计算实际 SHA-256；全局没填摘要时，控制面使用该宿主实测摘要生成创建负载。模板在就绪后改变，创建时再次核对已打开文件的 SHA-256，不能拿旧缓存掩盖变更。版本/摘要改变后，旧 READY 不能用于新版本调度。

目录缺失、摘要错误、网桥不存在、权限或扫描失败都如实报告，不用演示数据冒充就绪。首次注册后立即执行独立盘点，不等待一分钟才发现镜像缺失。

## 镜像同步协议

`SYNC_IMAGE` 任务负载：

```json
{
  "image_id": "ubuntu-2204",
  "source_url": "https://images.example.com/ubuntu.qcow2",
  "checksum": "64位小写SHA-256",
  "file_name": "ubuntu.qcow2",
  "image_generation": 1
}
```

任务使用同样的领取令牌、租约和持久化结果确认。成功/失败结果保留 `image_id`、`checksum`、`file_name`、`image_generation`，只有成功并匹配当前版本才可 READY。同步仅改变平台独立缓存，不修改原始本地模板、存量 VM 或它们的磁盘。

## 下载白名单和私有 OSS

- 只允许 HTTPS，正常验证系统信任的 TLS 证书。内网自签证书须由管理员安装到系统信任库，不可关闭校验。
- `KVM_IMAGE_ALLOWED_HOSTS` 为精确主机名，默认空表示拒绝新下载；不支持任意 URL 或通配符。
- `KVM_IMAGE_PRIVATE_HOSTS` 为额外允许 RFC1918/ULA 私网的主机名，必须也是 HTTPS 白名单子集。默认不允许私网；回环、未指定、link-local/云元数据和组播永不允许。
- 拒绝 URL 用户名/密码、fragment 和重定向。签名 OSS query 可以使用，但不写到错误/普通日志，任务日志按私有凭据等级保护。
- 每次连接只解析一次 DNS；所有返回 IP 都通过策略后，直接连接已验证 IP，不让第二次解析把公网域名重绑定到内部服务。
- HTTP 非 200、错误摘要、超大小、超缓存/真实磁盘安全余量或超时都明确失败。失败下载临时文件清理，不产生 READY。

配置示例：

```dotenv
KVM_IMAGE_ALLOWED_HOSTS=images.example.com,oss.example.internal
KVM_IMAGE_PRIVATE_HOSTS=oss.example.internal
KVM_IMAGE_MAX_GB=10
KVM_IMAGE_CACHE_MAX_GB=40
KVM_SAFETY_DISK_GB=10
```

## 路径、不可变缓存和回收

源镜像通过 Go `os.OpenRoot` 根目录句柄打开，禁止路径穿越及 symlink；打开后对实际描述符做类型、大小、SHA-256 核验，不再按原字符串重新打开。使用安全根句柄抵御中间目录被替换为越界符号链接的竞态。该机制以 Linux/macOS 上的目录句柄为基础，不能把管理员主动 bind-mount 的秘密目录当成安全模板目录。[Go 安全文件 API](https://go.dev/doc/go1.24)

创建时把已打开的源描述符复制到默认 `KVM_IMAGE_ROOT/.vmp-cache/<sha256>/<file_name>`。缓存目录为 Agent 所有、`0750 Agent:kvm`，内容 `0440`；父目录不允许组/其他用户写入，QEMU 只读访问，不可覆盖在用内容。镜像不得嵌入外部 backing/data 文件引用。原模板后来换路径、改字节或变 symlink，都不能改变已交付 VM 的 backing。

libvirt 动态 DAC 可将在用 backing 文件属主改为 QEMU 用户，Agent 兼容该变化：文件仍须为运行组中的 `0440` 普通文件并通过完整摘要核验，目录仍属于 Agent。不要对在用文件强行 chown、全局关闭 dynamic_ownership、递归修改缓存权限或删除 backing。

本地模板复制会增加一次真实存储占用，默认单镜像 10 GiB、缓存 40 GiB；需要按实际镜像和磁盘容量配置。下载同样保护 `KVM_SAFETY_DISK_GB`，不会为了缓存挤占存量虚机安全空间。相同内容的新 generation 可复用已有不可变文件，不重复下载或覆盖。

空间压力下，仅回收已从目录清单删除或过期版本、且完整库存证明没有任何域引用的缓存。包含外部域在内，均以只读 `qemu-img info --force-share --backing-chain --output=json` 检查；库存、磁盘、存储协议、链路路径任一无法核验都拒绝回收。当前登记版本即使暂未启用也保留，避免刚同步成功、尚未启用的内容被淘汰。不能手工删 `.vmp-cache` 或绕过错误强制回收。[QEMU backing 链查询](https://www.qemu.org/docs/master/tools/qemu-img.html)

## 分层交付与救援

创建前：先验证 arping/ping 为 iputils，再做绑定网桥的 ARP DAD 与 ICMP；真实目标 IP/MAC 应答及发送/接收统计共同构成证据。未知/Thomas 实现、权限/参数错误、执行取消/超时或证据缺失都是 `IP_PROBE_FAILED`，没有占用/空闲状态，不隔离或释放地址。新候选真冲突才带 IN_USE 与 `IP_ADDRESS_IN_USE`；已有域重试、关机/保留恢复只检查原 IP，冲突保留原盘/域/IP。运行幂等不自探测。探测无法消灭后续抢占，仍需 DHCP/IPAM 和分层交付核验。

启动后：按已校验托管域 UUID 查询 Guest Agent，核对预期 MAC 和 IPv4，再只读查询固定 cloud-init 结果文件，最后确认 SSH 端口可达。不是某台设备 ping 回应就宣称本 VM 已交付。

| 状态 | 含义和处理 |
| --- | --- |
| `GUEST_PENDING` | 域已启动，Guest Agent 或 cloud-init 尚未完成；保留域、磁盘和 IP，可打开控制台 |
| `NETWORK_PENDING` | IP/MAC 尚未匹配，或 cloud-init 完成后 SSH 不可达；保留现场，检查网络/防火墙 |
| `READY` | Guest IP/MAC、cloud-init、SSH 分层核验通过 |

创建任务在域启动后即确认资源存在，`provider_status=RUNNING` 与 `delivery_status` 分开；不再因 ping 超时销毁 VM 或清盘。周期库存继续只读更新交付状态。旧实例缺少扩展清单字段时，从受控 network-config/已验证域 XML 只读恢复；无法恢复则明确待核验，不改写既有 VM。

新实例 cloud-init 未完成不能重置密码，避免新的密码又被初始交付覆盖。等待完成或使用控制台检查；旧协议实例保持兼容。

`preflight` 显式跳过 Guest 查询，只做宿主文件/容量、工具和 libvirt `--readonly` 检查，不注册、写状态、领取任务或读取来宾文件。

## 验证范围和限制

本仓库自动化测试使用临时目录、假 virsh/qemu Runner 和真实本机 TLS 服务器，不连接业务宿主或操作真实 VM。测试包含实际 symlink 目录并发交换、模板变更、SHA/大小/版本、TLS/DNS/重定向/私网策略、缓存引用保护、ARP 冲突及 Guest Agent 分层结果，另在 Linux 隔离容器验证 `umask 077` 和不同 UID/相同运行组的动态 DAC 读取。真实 KVM、不同 Guest 镜像/架构、ARP 权限和现场 VLAN 的交付仍须在明确授权的隔离宿主验收，不能把这些单测当作业务宿主全场景实测。
