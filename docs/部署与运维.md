# Agent 部署与运维

VMP Agent 安装在每台 KVM 宿主机上。它主动连接控制面，上报宿主机资源和 libvirt 域，领取平台任务并通过本机 libvirt 执行。控制面不需要 SSH 密码，也不直接连接宿主机的 libvirt。

首次完整部署请先阅读 [部署主手册](https://github.com/lixiaokun777/vmp-backend/blob/main/docs/部署指南.md)，本文只补充 Agent 安装与运维细节。

## 1. 安全边界

- 新宿主机必须先以 `kvm-readonly` 运行。
- 只读模式通过 `virsh --readonly` 获取信息，不领取写任务。
- 平台专用存储目录必须与已有虚拟机目录完全隔离。
- 只有带合法 VMP metadata 且实例 UUID 匹配的域才属于平台。
- 删除前同时校验域 metadata 和实例目录内的 `manifest.json`。
- Agent 不得把 libvirt VNC 端口直接暴露到网络。
- 不要在承载重要虚拟机的宿主机上直接跳过只读验收。

## 2. 系统要求

当前发布脚本分别生成 Linux amd64/arm64 静态二进制。Ubuntu 22.04/24.04 可安装以下依赖：

以下完整安装清单适用于新宿主。已有业务虚拟机的宿主先检查现有工具，只补装缺失依赖；先用 `apt-get -s install 软件包名称` 审阅计划，若涉及升级或重启 libvirt/QEMU，应按现有运维流程安排窗口，不能直接套用整段安装命令。Agent 安装/升级本身不要求重启 libvirt、改变网桥或停止现有虚拟机。

```bash
sudo apt-get update
sudo apt-get install -y \
  qemu-kvm \
  qemu-utils \
  libvirt-daemon-system \
  libvirt-clients \
  genisoimage \
  iputils-ping \
  iputils-arping \
  libcap2-bin
```

确认 KVM 和 libvirt：

```bash
test -e /dev/kvm
sudo virsh --connect qemu:///system uri
sudo virsh --connect qemu:///system list --all
qemu-img --version
```

确认实际网桥名：

```bash
ip -br link show type bridge
ip address show br0
```

如果宿主机没有 Linux bridge，应先按现有网络规范配置。Agent 不负责创建网桥，也不会修改物理网卡配置。

seed 工具只需要选择一个并填写其实际绝对路径。本文及发布包示例使用 `KVM_SEED_TOOL_PATH=/usr/bin/genisoimage`；若选择 `cloud-localds`，安装 `cloud-image-utils` 后改为 `KVM_SEED_TOOL_PATH=/usr/bin/cloud-localds`。也支持 `mkisofs`。它们为新虚拟机制作 cloud-init 的账号、主机名和网络初始化介质，不会修改宿主网络或现有虚拟机。未配置时二进制默认 `cloud-localds`；配置缺失/错误不会自动切换工具。

## 3. 构建或获取发布包

从 0.5.3 发布页下载匹配架构的 `vmlease-agent-linux-amd64.tar.gz` 或 `vmlease-agent-linux-arm64.tar.gz` 和 `SHA256SUMS`。源码最低 Go 1.24，正式发布/推荐自编构建使用 Go 1.27.2。也可以在匹配工具链的构建机上执行：

`uname -m` 为 `x86_64` 时使用 amd64 包，`aarch64`/`arm64` 时使用 arm64 包。只下载一个架构时，在下载目录运行 `sha256sum --check --ignore-missing SHA256SUMS`，明确看到所下载包为 `OK` 后再解压；不加 `--ignore-missing` 会因为另一架构包未下载而报错。Agent 没有 `--version` 参数，不要以此检查版本，使用固定发布标签和 SHA-256。

```bash
VMP_AGENT_REPOSITORY='请替换为vmp-agent仓库地址'
git clone "$VMP_AGENT_REPOSITORY" vmp-agent
cd vmp-agent
go test ./...
./scripts/build-agent-bundle.sh
(cd dist && sha256sum -c SHA256SUMS)
```

不要在生产宿主机上长期保留完整构建工具链。建议在 CI 或独立构建机产出带版本号和 SHA-256 的发布包。

## 4. 安装目录

```bash
sudo install -d -m 0750 /opt/vmlease
sudo tar -xzf vmlease-agent-linux-amd64.tar.gz -C /opt/vmlease
cd /opt/vmlease/vmlease-agent
sudo cp conf/agent.env.example conf/agent.env
sudo chmod 600 conf/agent.env
```

目录结构：

```text
/opt/vmlease/vmlease-agent/
├── vmlease-agent
├── control.sh
├── conf/agent.env
├── logs/agent.log
└── run/
    ├── agent.pid
    └── state/                 # 私有凭据和任务日志，升级必须保留
```

Agent 不依赖 systemd。`control.sh` 负责启动、停止、状态和日志；停止时只发送 `SIGTERM`，不会自动 `kill -9`。它是 `nohup` 启动器，不内置开机自启或崩溃自动拉起，需组织现有受控进程管理机制补充。安装目录使用固定真实路径，不通过 `current` 符号链接启动；脚本会将 `/proc/PID/exe` 的真实路径与推导的二进制路径精确核对。

本文带 `sudo ./control.sh` 的命令以 root 部署为例。若选择专用账号，发布目录、配置和私有状态目录须归该账号所有，并配置其 libvirt、KVM 运行组、专用数据目录和 ARP 工具权限；安装、预检、启动、停止、重启、日志和升级都保持同一账号。不要把“root 预检通过”当成普通账号运行也通过，不能临时改用 root 绕过凭据/目录错误。`libvirt` 组本身有较高宿主管理权限，服务账号必须受信任；不要递归改主存量虚拟机或 libvirt 已转给 QEMU 的文件。

专用账号示例（先由管理员准备该账号权限和发布目录）：

```bash
sudo -u vmlease-agent /opt/vmlease/vmlease-agent/control.sh preflight
sudo -u vmlease-agent /opt/vmlease/vmlease-agent/control.sh start
sudo -u vmlease-agent /opt/vmlease/vmlease-agent/control.sh status
sudo -u vmlease-agent /opt/vmlease/vmlease-agent/control.sh logs 200
```

## 5. 准备隔离目录和镜像

```bash
sudo install -d -m 0750 /data/kvm-images/ephemeral
sudo install -d -m 0755 /data/cloud-init/images
```

要求：

- `KVM_STORAGE_ROOT` 只能存放 VMP 新建实例，不能指向 `/`、`/var/lib/libvirt/images` 或存量业务虚拟机目录。
- `KVM_IMAGE_ROOT` 存放只读基础镜像，不能与实例目录相同。
- 本地镜像名称必须与平台“镜像管理”中的文件名完全一致。
- 目标宿主的本地路径必须与平台定义对应。平台按各宿主实际镜像代次、摘要与网桥就绪调度，不要求全部宿主拥有每一种镜像；远程镜像需先在选定宿主同步成功。

```bash
sudo cp ubuntu-22.04-server-cloudimg-amd64.qcow2 /data/cloud-init/images/
sudo chmod 0644 /data/cloud-init/images/ubuntu-22.04-server-cloudimg-amd64.qcow2
qemu-img info /data/cloud-init/images/ubuntu-22.04-server-cloudimg-amd64.qcow2
sha256sum /data/cloud-init/images/ubuntu-22.04-server-cloudimg-amd64.qcow2
```

镜像应包含 cloud-init。要使用密码重置功能，镜像还必须预装并启用 `qemu-guest-agent`；Agent 不会在虚拟机首次启动时联网安装软件包。

## 6. 配置只读纳管

编辑发布目录下的 `conf/agent.env`，不是当前目录的 `.env`。`control.sh` 用 shell 直接加载配置，文件只能由受信任管理员维护；含空格、`$`、`#`、`&` 等特殊字符的值要正确引用。自定义配置用 `sudo env VMLEASE_AGENT_CONFIG=/etc/vmlease/agent.env /opt/vmlease/vmlease-agent/control.sh preflight`，启动同理。直接运行二进制不会自动读该文件，也没有 `--config` 参数。初次纳管必须保持：

```dotenv
AGENT_MODE=kvm-readonly
KVM_WRITE_ENABLED=false
KVM_WRITE_CONFIRMATION=disabled
```

必须按环境修改：

```dotenv
AGENT_NAME=node01
AGENT_MANAGEMENT_IP=10.0.0.21
CONTROL_PLANE_URL=http://10.0.0.10:8080
AGENT_BOOTSTRAP_TOKEN=与控制面一致的引导令牌
AGENT_HOST_ID=
AGENT_RUNTIME_TOKEN=
AGENT_STATE_DIR=

KVM_LIBVIRT_URI=qemu:///system
KVM_VIRSH_PATH=/usr/bin/virsh
KVM_QEMU_IMG_PATH=/usr/bin/qemu-img
KVM_SEED_TOOL_PATH=/usr/bin/genisoimage
KVM_PING_PATH=/usr/bin/ping
KVM_ARPING_PATH=/usr/bin/arping

KVM_STORAGE_ROOT=/data/kvm-images/ephemeral
KVM_IMAGE_ROOT=/data/cloud-init/images
KVM_CACHE_ROOT=
KVM_IMAGE_ALLOWED_HOSTS=
KVM_IMAGE_PRIVATE_HOSTS=
KVM_IMAGE_MAX_GB=10
KVM_IMAGE_CACHE_MAX_GB=40
KVM_ALLOWED_BRIDGES=br0
KVM_RUNTIME_GROUP=kvm

ALLOCATABLE_CPU=0
ALLOCATABLE_MEMORY_MB=40960
ALLOCATABLE_DISK_GB=0
KVM_SAFETY_MEMORY_MB=10240
KVM_SAFETY_DISK_GB=10
```

`CONTROL_PLANE_URL` 不要以 `/` 结尾，应填写 Agent 实际可访问的 Web 根地址，例如 `https://vmp.example.com`。Agent 会在该地址后追加 `/api/v1/...`。

`AGENT_MANAGEMENT_IP` 填写控制节点实际可达的宿主 IP（上例 `10.0.0.21` 需替换），用于同源 VNC/串口代理的固定拨号。仅填写 IPv4/IPv6 字面量，不带 URL、端口、网段、域名或 IPv6 zone；非法非空配置会在启动前报中文错误并退出。留空时注册不提交该字段，后端保留宿主已有管理地址，但不会补全空地址。注册链路可能经过 NAT/反向代理，因此 Agent 不使用连接来源或控制台 URL 猜测 IP；启用控制台的新宿主或原管理地址为空的宿主须显式配置。

新宿主首次注册保留 `AGENT_HOST_ID` 和 `AGENT_RUNTIME_TOKEN` 为空，后端自动签发宿主专属令牌并存入私有状态目录；成功注册后可以清空引导令牌。`control.sh` 将空 `AGENT_STATE_DIR` 设为当前发布目录的 `run/state`，直接执行二进制时则默认 `/var/lib/vmlease-agent`。

资源上限规则：

- `ALLOCATABLE_CPU=0`：固定预算按宿主逻辑 CPU 总数计算，不是当前空闲 CPU。
- `ALLOCATABLE_MEMORY_MB`：固定内存总预算，单位 MiB；默认 40960（40 GiB），0 时取物理总内存减 `KVM_SAFETY_MEMORY_MB`；非零值的实际预算取配置值与该上限的较小值。
- `ALLOCATABLE_DISK_GB=0`：固定预算取专用目录所在文件系统总容量减 `KVM_SAFETY_DISK_GB`，不是当前空闲空间；非零值按 GiB 计，实际预算取配置值与该上限的较小值。
- 实测安全内存为 `MemAvailable - KVM_SAFETY_MEMORY_MB`，实测安全磁盘为所在文件系统当前可用空间减 `KVM_SAFETY_DISK_GB`；与固定预算分开上报，调度必须同时满足二者。

对于已有虚拟机较多的宿主机，建议显式设置保守上限，不要依赖自动值。

## 7. 预检和启动

```bash
cd /opt/vmlease/vmlease-agent
sudo ./control.sh preflight
sudo ./control.sh start
sudo ./control.sh status
sudo ./control.sh logs 200
```

预检检查工具路径是否存在、平台存储/镜像目录是否存在且不是符号链接、允许网桥、只读 libvirt 连接、宿主机资源和域盘点；跳过 Guest 查询，不注册、不写私有状态、不领取任务。只读模式正常输出 `CORDONED`、写模式正常输出 `ACTIVE`，返回 0；检查项失败为 `DEGRADED`，返回 1；驱动错误可输出 `ERROR`，配置错误返回 2。失败时不得开启写模式。

预检不校验控制面连通性、注册令牌、私有状态目录锁、控制台密钥/Origin，也不完整验证工具可执行、libvirt 写权限和 arping 的 `CAP_NET_RAW`。应额外以实际运行账号确认工具可执行、所需组/目录/ARP 权限；网桥还须在平台矩阵中为启用就绪状态。`start` 等待约 1 秒只确认进程未退出，`status` 只确认 PID 对应进程：首次引导令牌错误时注册可能持续重试，已有宿主凭据失效也可能在初始化时直接退出，进程活着不代表纳管成功。`logs 200` 会持续跟踪最后 200 行，按 Ctrl+C 只结束日志查看。

启动成功后，在平台“宿主机”页面检查：

- Agent 模式为 `kvm-readonly`；
- 宿主机状态为 `CORDONED`；
- CPU、内存、磁盘、网桥和版本正确；
- 宿主管理 IP 为控制节点可达的地址；
- 已有虚拟机标记为 `EXTERNAL`，而不是 `MANAGED`；
- 最近心跳持续更新。

## 8. 开启写模式

只有完成以下检查后才允许开启：

1. 平台专用存储目录为空且与存量目录隔离。
2. 本地镜像、网桥和测试 IP 已准备完成。
3. 平台网络地址池不与 DHCP 或现有设备冲突。
4. 宿主机资源配额保守且不会挤占现有虚拟机。
5. 已在非关键宿主机完成创建和删除演练。

修改配置：

```dotenv
AGENT_MODE=kvm
KVM_WRITE_ENABLED=true
KVM_WRITE_CONFIRMATION=enable-kvm-write
```

再次预检并重启：

```bash
sudo ./control.sh preflight
sudo ./control.sh restart
sudo ./control.sh status
```

写模式会设置 libvirt 运行组、创建 qcow2 增量盘并执行写入型 `virsh`。可以使用 root 或具备所需 libvirt/运行组权限的专用账号，升级应沿用原账号。非 root 的 ARP DAD 工具需 CAP_NET_RAW；如发行版未预设能力，由管理员配置工具权限，例如限制可执行用户后给 arping 设置 `cap_net_raw+ep`。不要给整个 Agent 设置额外网络能力或把 libvirt TCP 暴露到公网。

基础模板如果是只读挂载，要把 `KVM_CACHE_ROOT` 指向独立、Agent 所有且父目录无组/其他用户写权限的目录。源模板复制会增加真实空间占用，配置缓存上限和磁盘安全余量；默认内容寻址缓存为 `KVM_IMAGE_ROOT/.vmp-cache`。远程下载需先配置 `KVM_IMAGE_ALLOWED_HOSTS`，私有 OSS 再添加 `KVM_IMAGE_PRIVATE_HOSTS`；证书加入系统信任库，不能关闭 TLS 校验。完整规则见 [镜像与交付安全](镜像与交付安全.md)。

## 9. 控制台代理

当前推荐 Agent `0.5.3`、后端 `0.5.3`、前端 `0.5.2`。旧 `0.5.0` 候选已标为验收未通过，请勿部署。Agent 核销票据前和底层建连后均实时核验域 UUID、名称、元数据与运行状态；现有托管域 UUID 必须和平台实例 UUID 一致。若历史手工创建域不满足该身份约束，保持拒绝，核查来源，不要通过改名或清除元数据绕过校验。

`0.5.3` 修复私有 umask 下镜像缓存摘要目录的 QEMU 访问权限。目录须为 Agent 自有、所属 KVM 运行组的 0750，文件须为 0440 且属于正确运行组；libvirt 动态 DAC 把在用 backing 文件转给 QEMU 用户是合法行为，不能强行把文件改回 Agent。不得用 0777、开放组写、关闭 AppArmor 或全局停用 dynamic_ownership 绕过问题。此前已有 0700 摘要目录时，仅读取缓存或点击“同步”不保证自动修正；须管理员核验精确目录的所有权、摘要和关联实例，再仅将该已验证目录修正为 0750，然后重试。不能递归 chmod/chown、删除 `.vmp-cache` 或更改在用文件属主。

控制台功能可选。禁用时保持监听地址、内部代理地址和签名密钥为空。浏览器始终连接平台同源入口，控制节点再连接 Agent；19090 只允许控制节点 IP，不能对用户网段或公网开放。内部 WS 可用于内网连接，HTTPS 用户入口不要求把内部 Agent 也暴露为公网 WSS：

```dotenv
CONSOLE_LISTEN_ADDR=0.0.0.0:19090
CONSOLE_PUBLIC_URL=ws://10.0.0.21:19090
CONSOLE_SIGNING_KEY=与控制面完全一致的至少32位随机值
CONSOLE_ALLOWED_ORIGINS=http://10.0.0.10:8080
```

```bash
curl http://127.0.0.1:19090/health
```

生产 HTTPS 页面使用控制面的同源 `wss://` 入口。内部控制节点到 Agent 可使用受防火墙保护的 `ws://`；Agent 当前本身不提供 TLS 证书配置，内部 `wss://` 需要另外部署受信任的 TLS 代理，并核验固定管理 IP 拨号与证书/代理地址相匹配。不是要求浏览器直接访问宿主。Agent 代理端口仅允许控制节点 IP，不能对平台用户网段或公网开放，Origin 填浏览器实际的平台 Origin（协议和域名/IP，非默认端口须保留，不带路径），不能用 `*`。

## 10. 常用命令

```bash
./control.sh preflight
./control.sh start
./control.sh status
./control.sh logs 200
./control.sh restart
./control.sh stop
```

日志默认位于 `logs/agent.log`。应通过 logrotate 或日志采集系统设置大小和保留周期，避免长期运行占满宿主机磁盘。

logrotate 示例：

```text
/opt/vmlease/vmlease-agent/logs/agent.log {
    daily
    rotate 14
    size 20M
    compress
    missingok
    copytruncate
}
```

保存为 `/etc/logrotate.d/vmlease-agent` 后，可以用 `sudo logrotate -d /etc/logrotate.d/vmlease-agent` 检查配置。`copytruncate` 不需要重启 Agent，但轮转瞬间可能丢失极少量日志；已接入集中日志系统时优先使用日志采集侧的轮转策略。

## 11. 升级与回滚

升级步骤：

1. 在平台暂停新增申请与审批，把宿主机暂停调度，并核查待执行和运行中的任务；暂停调度只阻止新增放置，不等于禁止到期/删除等已产生的任务。必要时配合控制面维护窗口，不能仅凭 `CORDONED` 假定没有任务。
2. 记录原运行账号、PID、安装路径、配置/状态/数据/缓存目录、身份和二进制 SHA-256；不要把凭据值贴到日志或公开文档。
3. 用原账号执行 `./control.sh stop`，确认旧进程已结束后，再备份原二进制、脚本、配置和完整 `AGENT_STATE_DIR`，得到一致的凭据/任务日志快照。备份目录 `0700`、文件 `0600`，不可只备份 `credentials.json`。
4. 解压新包到临时目录，比较配置示例中的新增字段。
5. 替换二进制和 `control.sh`，保留当前配置。
6. 执行预检，再启动并观察心跳和日志。

```bash
sudo ./control.sh stop
sudo cp vmlease-agent.new vmlease-agent
sudo chmod 700 vmlease-agent control.sh
sudo ./control.sh preflight
sudo ./control.sh start
sudo ./control.sh logs 200
```

建议逐台升级。先停止再替换，不能边运行边覆盖二进制：Linux 的 `/proc/PID/exe` 可能变为 `(deleted)`，此时脚本的精确路径核对可能无法识别旧进程。停止超过 20 秒会返回失败，不自动强杀；应核查进程/任务后再处理，不能继续替换或另起第二个 Agent。

停止 Agent 不会停止现有虚拟机，但期间平台任务不能执行。回滚必须先核查控制面协议、当前任务、metadata/清单和状态格式是否兼容，再停止新版、恢复已验证旧二进制/脚本及匹配配置，保持原账号、宿主 ID 和当前完整状态目录。默认不要把旧状态快照直接覆盖已处理新任务的状态，否则可能丢失完成回执或使用已撤销的凭据。若必须恢复状态备份，应由管理员联合数据库任务/回执和真实域核查。先只读启动验收，再受控恢复写模式；不支持把新专属身份/租约协议随意退回旧 0.4.x 共享令牌版，也不应为回滚删除域、磁盘或缓存。

后端 0.5.3 / 前端 0.5.2 本轮发布不改变 Agent 协议，已运行有效独立凭据的 Agent 0.5.3 不需重装或轮换。以下迁移仅用于旧共享身份环境。

### 从共享令牌旧版迁移

1. 先升级控制面，确保支持专属宿主凭据和任务租约协议，再逐台升级 Agent；不要把旧 Agent 与新协议混合写入运行。
2. 先停止目标 Agent 并排空任务，使用前端 0.5.2 的“宿主机 → 签发凭据 / 轮换凭据”入口，取得原宿主 UUID 和只显示一次的专属运行令牌；点击复制 agent.env 两行片段导入本台。管理员 API `POST /api/v1/hosts/{id}/credentials/rotate` 仅作为旧前端应急 / 自动化入口。按[完整部署手册第 22.6.1 节](https://github.com/lixiaokun777/vmp-backend/blob/main/docs/新手部署手册.md)核对宿主和执行。轮换会使旧令牌立即失效。
3. 停止对应 Agent，在 `conf/agent.env` 同时设置 `AGENT_HOST_ID` 和 `AGENT_RUNTIME_TOKEN`，保护文件权限为 `0600`。
4. 启动新版 Agent。它把凭据导入私有状态目录，并携带专属令牌恢复原宿主，不能通过引导令牌接管同名宿主。
5. 验证该宿主心跳和任务接口成功后清空这两个导入变量，日常重启继续读 `credentials.json`。引导令牌也可清空。

升级过程中不要清空 `run/state`、手工删除 `task.json` 或换目录重启来绕过未完成任务。`DONE` 日志只会重发结果；执行中断的重启任务会明确报告不确定状态，不再次重启业务机。

## 12. 故障排查

### 注册返回 401

首次纳管确认 `AGENT_BOOTSTRAP_TOKEN` 与控制面一致；已有宿主恢复使用保存的专属运行凭据，不是引导令牌。确认 `CONTROL_PLANE_URL` 正确，凭据轮换后需要导入新令牌；不能复制另一台宿主的身份或清空状态目录来重注册。同名宿主不能通过 bootstrap 接管。

### 心跳或任务返回 401

确认当前宿主的专属运行凭据有效，宿主 UUID 与凭据对应。轮换后需要导入新专属令牌；吊销后 Agent 应保持停用。不要复制另一台宿主的凭据，也不要改回平台旧版共享令牌。日志不会显示令牌正文。

### 创建回滚尚未完成

这表示 Agent 不能确认 libvirt 域已停止或取消定义，已保留系统盘、清单和 `rollback-pending.json`。先恢复 libvirt 通信，在实例页重试交付或执行平台删除；重试会重新验证 metadata，再安全补偿。不要手工删盘，不能因为“创建失败”就假定真实域不存在。

### 未确认结果或任务租约丢失

临时网络故障时，结果会保存在私有状态目录，连接恢复后自动重发。租约丢失时 Agent 停止继续操作，等待控制面重排。若为重启任务，执行结果不确定，需要用只读查询核查实际状态后手工重新发起。状态文件损坏时程序拒绝执行，恢复受保护的匹配备份，不要直接删除日志绕过保护。

SIGTERM、工作截止及租约丢失都只记录本地补偿标记保留现场，不继续后台销毁或删盘。未确认成功结果分任务缓存，不被另一任务完成清空；最多 256 条。达到上限时停止进一步领取，当前结果仍保留，需要管理员核查控制面任务/回执和真实域后恢复。后端回执窗口为 60 天，超过窗口且任务已清表的删除完成记录可能不能自动确认；不要批量删缓存解除限制，应核查对应 `task_id`、`task_type`、`saved_at` 后逐项处理。

### libvirt 预检失败

```bash
sudo virsh --readonly --connect qemu:///system uri
sudo virsh --readonly --connect qemu:///system list --all
```

检查 libvirtd/virtqemud 状态、Unix socket 权限和 URI。不要为解决本地权限问题开放 libvirt 远程 TCP。

### 网桥预检失败

```bash
test -d /sys/class/net/br0/bridge
ip address show br0
```

`KVM_ALLOWED_BRIDGES` 必须填写 Linux bridge，而不是物理网卡、bond 从接口或不存在的名称。

### 创建时报镜像路径错误

镜像必须是 `KVM_IMAGE_ROOT` 内的普通文件。平台填写的绝对路径也必须位于该目录内；`../` 路径会被拒绝。

### 创建时报 IP 已占用

Agent 在写磁盘前联合 ARP DAD 和 ICMP 探测目标 IP；禁 ICMP 的设备可以被 ARP 发现。冲突回报 `IP_ADDRESS_IN_USE`，控制面隔离并自动换 IP。工具权限、接口或探测异常会明确失败，不可绕过探测把它当成空闲地址。

### 虚机运行但交付未就绪

检查平台的 `GUEST_PENDING`/`NETWORK_PENDING` 提示，并使用同源 VNC/串口查看 cloud-init、网桥、VLAN、网关、Guest Agent 和防火墙。域与磁盘、IP会保留，不再因为 ping 超时回滚；后台库存继续核验 IP/MAC、cloud-init 和 SSH，完成后更新 READY。新实例初始化未完成不能重置密码，以免被初始交付覆盖。

### 删除被拒绝

Agent 只删除同时满足合法域 metadata、实例 UUID、域名和 `manifest.json` 的资源。不要手工伪造这些文件；先确认该域是否确实由 VMP 创建。

### 控制台连接异常

先检查 Agent 日志中的 Origin、票据和核销错误，再检查：

```bash
sudo virsh domdisplay 虚拟机名称 --type vnc
sudo virsh console 虚拟机名称
```

票据只能使用一次，失效后应在页面点击“重新连接”。不得把 libvirt VNC 改为监听全部地址。

## 13. 卸载

```bash
cd /opt/vmlease/vmlease-agent
sudo ./control.sh stop
```

确认平台没有待执行任务，并将宿主机移出调度后，才可以移除 Agent 目录。卸载 Agent 不会删除虚拟机。平台专用实例目录可能仍包含磁盘，未核对实例归属前不得删除。
