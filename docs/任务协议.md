# Agent 任务协议

## 领取、续租与结果确认

`GET /api/v1/agents/{host_id}/tasks/next` 返回 `id`、`type`、`payload`、`claim_token` 和 RFC3339 格式的 `lease_until`。领取令牌只标识当前执行者，不是宿主运行令牌；不得写入普通日志。

控制面租约为 60 秒。Agent 在执行前把任务落盘，每 10 秒调用 `POST /api/v1/agents/{host_id}/tasks/{task_id}/renew`，请求体为 `{"claim_token":"当前领取令牌"}`，响应返回新的 `lease_until`。网络临时失败可在原截止前重试；到期或收到 `409` 必须立即取消执行。一次 worker 操作最多 15 分钟，任务始终串行，心跳和库存盘点独立运行。

`POST /api/v1/agents/{host_id}/tasks/{task_id}/result` 在原结果字段外必须包含 `claim_token`。结果先原子落盘，控制面确认 `2xx` 后才删除本地待确认记录；临时 HTTP 故障时下次循环或重启继续重发。控制面应保存幂等完成回执，同一领取令牌和同一结果重复提交返回成功，旧领取令牌或冲突结果返回 `409`。

旧领取令牌被替换后，Agent 仅为相同任务 ID、类型和负载复用已完成的成功结果；IP 等负载发生变化必须重新执行。执行中重启、仅有领取记录时，先续租确认所有权，再恢复幂等任务。`REBOOT_INSTANCE` 不能确认副作用是否发生，不自动重放，回报 `EXECUTION_UNCERTAIN`，控制面必须将其明确失败而不是通用重试。

私有状态目录保存当前待执行/待确认记录，以及按任务 ID、类型、负载摘要隔离的多条未确认成功结果。另一任务的完成不会覆盖/清除旧成功结果；只清理对应摘要。文件包含领取令牌和可能的 crypt 摘要，目录 `0700`、文件 `0600`。缓存最多 256 条，超过上限时保留当前任务且停止领取，不淘汰旧结果。目录损坏或身份不匹配时也停止领取，不绕过校验。

## CREATE_INSTANCE

必填负载字段：

| 字段 | 说明 |
| --- | --- |
| `instance_id` | 平台实例 UUID，同时作为域 UUID 和受控目录名 |
| `name` | libvirt 域名称 |
| `cpu` | vCPU 数量 |
| `memory_mb` | 内存，单位 MB |
| `disk_gb` | 系统盘容量，单位 GB |
| `image_file` | `KVM_IMAGE_ROOT` 下的基础镜像文件名，不允许目录分隔符 |
| `image_path` | 管理员定义的本地镜像路径；相对路径和绝对路径都必须位于 `KVM_IMAGE_ROOT` 内 |
| `image_id` / `image_checksum` / `image_generation` | 控制面选定的宿主镜像版本和实际 SHA-256；远程来源必须已由此宿主同步 |
| `bridge` | 必须位于网桥白名单 |
| `mac_address` | 控制面按实例 UUID 稳定生成的 QEMU MAC；旧任务缺失时由 Agent 使用同一算法补齐 |
| `ip_address` | 静态 IPv4 地址 |
| `prefix_length` | IPv4 前缀长度 |
| `gateway` | 必须与 IP 处于同一子网 |
| `dns_servers` | IPv4 DNS 地址数组 |
| `username` | cloud-init 初始用户 |
| `password_hash` | 可选，只接受加密摘要 |
| `ssh_authorized_key` | 可选，只接受单行合法 SSH 公钥 |

`password_hash` 和 `ssh_authorized_key` 至少提供一项。Agent 使用 `mac_address` 同时生成 libvirt 域网卡和 cloud-init 网络配置，网络配置按 MAC 匹配实际设备，不再依赖首次启动时的网卡重命名。

创建时，Agent 将实例目录设为 `0750`、系统盘设为 `0660`、cloud-init seed 设为 `0640`，并将这些路径的组设为 `KVM_RUNTIME_GROUP`。这样 QEMU 可访问平台资源，同时不向其他系统用户开放权限。

在创建任何磁盘或定义域之前，Agent 使用 iputils `KVM_ARPING_PATH` 的 DAD 模式，并结合 `KVM_PING_PATH` 检测目标 IP。任何一项发现占用，结果携带 `error_code=IP_ADDRESS_IN_USE`，不会创建实例目录/磁盘或定义域。ARP 工具/权限错误也不能当成空闲地址。控制面隔离冲突地址、更换候选 IP 并重试原任务。

域成功启动即确认资源存在，结果 `provider_status=RUNNING`，交付状态分别为 `GUEST_PENDING`、`NETWORK_PENDING` 或 `READY`。Guest Agent 核验 IP/MAC、固定 cloud-init 结果文件和 SSH 可达性，周期盘点继续更新；不以 ping 超时删除运行域或磁盘。磁盘/定义/启动等真正失败仍走安全回滚：查询并验证 metadata、确认停止并取消定义，再确认域不存在后才允许清理受控目录。

停止/取消定义/再次查询任一步失败，会保留磁盘、清单和 `rollback-pending.json`，报告 `ROLLBACK_PENDING`。下次创建重试仅在补偿标记与实例身份一致、目标域仍属于平台时继续安全补偿，再重新交付。补偿不能触碰替换成同名的外部域。领取租约丢失、SIGTERM 和工作超时等任意执行取消，只记录本地补偿标记保留现场；正常业务报错的补偿也使用原执行上下文派生的 15 秒上限，取消发生在补偿中会立即停止。在调用停止、取消定义和删除目录前再次检查上下文，不使用后台上下文延长所有权。

## DELETE_INSTANCE

负载只包含 `instance_id` 和 `name`。Agent 会在执行 `destroy` 或 `undefine` 之前检查：

1. 域 XML 必须携带平台 namespace、`managed-by=vmlease` 和相同实例 UUID。
2. 受控目录必须位于 `KVM_STORAGE_ROOT/{instance_id}`。
3. 目录不能是符号链接，`manifest.json` 的 UUID 和名称必须与任务一致。

域和目录都不存在时，删除任务按幂等成功处理。

## START_INSTANCE / STOP_INSTANCE / REBOOT_INSTANCE

三种任务都只包含 `instance_id` 和 `name`。执行前与删除任务使用相同的双重所有权校验：

1. libvirt 域必须由平台管理，且实例 UUID 和域名一致。
2. 受控目录和 `manifest.json` 必须与实例一致。
3. 已开机的实例再收到开机任务、已关机的实例再收到关机任务，按幂等成功处理。

`STOP_INSTANCE` 使用 libvirt `shutdown` 进行优雅关机，不会自动执行强制断电。

## RESET_INSTANCE_PASSWORD

负载包含 `instance_id`、`name`、`username` 和 `password_hash`。其中 `password_hash` 必须是 crypt 格式摘要，禁止下发明文密码。

Agent 完成平台域和受控目录双重所有权校验，并确认虚拟机处于运行状态后，通过 QEMU Guest Agent 的 `guest-set-user-password` 写入加密密码。新建实例的域 XML 包含 `org.qemu.guest_agent.0` 通道，cloud-init 负责启动镜像中预装的 `qemu-guest-agent`。平台镜像必须预装该软件，创建流程不依赖虚拟机访问公网软件源。Guest Agent 不可用时任务明确失败，不会回退到向磁盘注入明文或破坏性重建。

新协议实例还要确认 cloud-init 完成，避免重置后的密码被初始化再次覆盖；旧清单维持兼容。

## SYNC_IMAGE / 宿主就绪矩阵

`SYNC_IMAGE` 包含 `image_id/source_url/checksum/file_name/image_generation`，成功结果回传相同标识。只允许配置白名单的 HTTPS 镜像和明确允许的私有 OSS；实际下载、大小与 SHA-256 核验、格式和外部 backing 检查后，原子发布到 `.vmp-cache/<sha256>/<file_name>`。失败不报告 READY。

Agent 使用专属凭据读取 `/api/v1/agents/{host_id}/catalog`。心跳 `facts.images` 携带每个镜像的 `image_id/file_name/checksum/generation/status/error`，`facts.networks` 携带 `bridge/ready/error`，`readiness_complete` 表示真实完成清单检查。来源、摘要或 generation 改变，旧 READY 不得复用。

具体安全边界、实时余量字段与回收策略见 [镜像与交付安全](镜像与交付安全.md)。
