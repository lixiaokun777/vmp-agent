# Agent 任务协议

## CREATE_INSTANCE

必填负载字段：

| 字段 | 说明 |
| --- | --- |
| `instance_id` | 平台实例 UUID，同时作为域 UUID 和受控目录名 |
| `name` | libvirt 域名称 |
| `cpu` | vCPU 数量 |
| `memory_mb` | 内存，单位 MB |
| `disk_gb` | 系统盘容量，单位 GB |
| `image_file` | `KVM_IMAGE_ROOT` 下的基础镜像文件名，不允许目录分隔符 |
| `bridge` | 必须位于网桥白名单 |
| `ip_address` | 静态 IPv4 地址 |
| `prefix_length` | IPv4 前缀长度 |
| `gateway` | 必须与 IP 处于同一子网 |
| `dns_servers` | IPv4 DNS 地址数组 |
| `username` | cloud-init 初始用户 |
| `password_hash` | 可选，只接受加密摘要 |
| `ssh_authorized_key` | 可选，只接受单行合法 SSH 公钥 |

`password_hash` 和 `ssh_authorized_key` 至少提供一项。`mac_address` 可选；不提供时由 libvirt 生成。

创建时，Agent 将实例目录设为 `0750`、系统盘设为 `0660`、cloud-init seed 设为 `0640`，并将这些路径的组设为 `KVM_RUNTIME_GROUP`。这样 QEMU 可访问平台资源，同时不向其他系统用户开放权限。

## DELETE_INSTANCE

负载只包含 `instance_id` 和 `name`。Agent 会在执行 `destroy` 或 `undefine` 之前检查：

1. 域 XML 必须携带平台 namespace、`managed-by=vmlease` 和相同实例 UUID。
2. 受控目录必须位于 `KVM_STORAGE_ROOT/{instance_id}`。
3. 目录不能是符号链接，`manifest.json` 的 UUID 和名称必须与任务一致。

域和目录都不存在时，删除任务按幂等成功处理。

## START_INSTANCE / STOP_INSTANCE / REBOOT_INSTANCE

三种任务都只包含 `instance_id` 和 `name`。执行前与删除任务使用相同的双重所有权校验：

1. libvirt 域必须由平台管理，且实例 UUID 和域名一致。
2. 受控目录和 `manifest.json` 必须与实例一致。
3. 已开机的实例再收到开机任务、已关机的实例再收到关机任务，按幂等成功处理。

`STOP_INSTANCE` 使用 libvirt `shutdown` 进行优雅关机，不会自动执行强制断电。
